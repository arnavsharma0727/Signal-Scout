# Automated public-source discovery

Run `npm run discover:leads` from the repository root. It needs no API keys and does not use the Supabase service-role key. For focused work, add `--topic "specific event or entity"` (up to four repeatable topics). The run can also combine at most four current labels from Bluesky's public trend API with at most four headlines from the already-reviewed Global Voices and The Conversation feeds. It then checks no more than eight total seeds through Bluesky's public search API and, when a topic has a relevant listed community, the official Stack Exchange API. Each publisher feed is fetched once per run, requests are bounded, and topic searches are capped at four concurrent calls. Publisher headline seeds preserve their title and URL as provenance; they are not treated as evidence that a public conversation exists.

The command prints a JSON review queue to standard output. Each candidate includes the discovery source, citation URLs, publication dates, author attribution, source class, observed cross-source coverage, provider errors, and qualification gaps. Bluesky post text is transient and is not included in output; its indexed results can include media relays and institutional accounts, so the count is not a count of genuine conversation. Stack Exchange results are retained only when the API reports the individual CC BY-SA 4.0 license. Publisher metadata is filtered through the existing feed connectors, which discard article bodies and validate host, date, attribution, and feed rights.

`candidate_for_original_source_review` means the topic has at least one recent API search result and a matching item from one reviewed licensed publisher operator. Search hits can be automated relays or organizations, so this is a queue label—not a claim of person-to-person conversation, independent corroboration, a qualified lead, or a confidence score. Queue ordering uses evidence-class/operator coverage, not the raw result count. `insufficient_cross_source_evidence` means that combination was not found in this bounded run; it does not establish that no relevant evidence exists. Search results, trends, and feed availability are partial and can change between runs.

No automated classifier can establish that a post supports or contradicts a specific thesis from citation metadata alone. Before a candidate can be published as a lead, a researcher must inspect the original sources and attest to claim-specific supporting and counter-evidence, source-operator independence, alternative explanations, and a test that could disconfirm the thesis. The run never writes to Supabase, activates a lead, or publishes to the shared queue.

The current source mix is intentionally modest and transparent: Bluesky is a single social operator; Stack Exchange is expert Q&A rather than a general-population forum; Global Voices and The Conversation are their own publisher operators. Provider ranks are not a proxy for country, population attention, prevalence, or market behavior. GDELT is not called by this discovery job because it was returning public rate limits during verification; the app's visitor-triggered GDELT integration remains separate. This is targeted API orchestration—not a web crawler, exhaustive sweep, or automated lead publisher.
