# Automated public-source discovery

Run `npm run discover:leads` from the repository root. It needs no API keys and does not use the Supabase service-role key. For focused work, add `--topic "specific event or entity"` (up to four repeatable topics). Explicit topics are exclusive: the command checks only those topics and does not add unrelated Bluesky trends or publisher headlines. Without `--topic`, it seeds a small queue from at most four current Bluesky trend labels and four recent headlines from the already-reviewed Global Voices and The Conversation feeds. Each topic is cross-checked through Bluesky's public search API and one public Lemmy instance (`lemmy.world`); when a topic maps to a relevant listed community, it also checks the official Stack Exchange API. Each publisher feed is fetched once per run, requests are bounded, and topic searches are capped at four concurrent calls. Lemmy contributes original links, titles, dates, and usernames to the CLI output; post bodies are used transiently for topic and headline-echo triage and are not printed or retained. Results count toward topic coverage only when at least two meaningful query terms match. That is a retrieval filter, not proof of relevance. Publisher headline seeds preserve their title and URL as provenance; they are not treated as evidence that a public conversation exists.

The command prints a JSON review queue to standard output. Each candidate includes the discovery source, citation URLs, publication dates, author attribution, source class, observed cross-source coverage, provider errors, qualification gaps, and separate triage notes. Bluesky and Lemmy post text is transient and is not included in output. When a post begins with a matched reviewed-publisher headline, it is labeled as a headline echo and excluded from the non-headline author count; link-only posts are also excluded. These lexical heuristics can misclassify posts and do not establish that non-headline text is relevant, original, substantive, human-authored, or independent. They do not identify automated or institutional accounts and never substitute for opening the original. The JSON reports raw search hits separately from query-matching posts and distinct authors with non-headline text. Stack Exchange results are retained only when the API reports the individual CC BY-SA 4.0 license. Publisher metadata is filtered through the existing feed connectors, which discard article bodies and validate host, date, attribution, and feed rights.

`candidate_for_original_source_review` means the topic has a matching item from one reviewed licensed publisher operator and either two distinct non-headline authors across Bluesky/Lemmy or at least one licensed Stack Exchange question. Lemmy is one instance and one incomplete federated index—not an independent population sample. Search hits can still be automated relays, organizations, irrelevant matches, or a narrow sample, so this is a queue label—not a claim of representative conversation, independent corroboration, a qualified lead, or a confidence score. Queue ordering uses non-headline author and evidence-class/operator coverage, not raw social-hit counts. `insufficient_cross_source_evidence` means that combination was not found in this bounded run; it does not establish that no relevant evidence exists. Search results, trends, and feed availability are partial and can change between runs.

No automated classifier can establish that a post supports or contradicts a specific thesis from citation metadata alone. Before a candidate can be published as a lead, a researcher must inspect the original sources and attest to claim-specific supporting and counter-evidence, source-operator independence, alternative explanations, and a test that could disconfirm the thesis. The run never writes to Supabase, activates a lead, or publishes to the shared queue.

The current source mix is intentionally modest and transparent: Bluesky is a single social operator; Lemmy search is limited to one federated instance; Stack Exchange is expert Q&A rather than a general-population forum; Global Voices and The Conversation are their own publisher operators. Provider ranks are not a proxy for country, population attention, prevalence, or market behavior. GDELT is not called by this discovery job because it was returning public rate limits during verification; the app's visitor-triggered GDELT integration remains separate. This is targeted API orchestration—not a web crawler, exhaustive sweep, or automated lead publisher.
