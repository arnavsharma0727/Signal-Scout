# Company profile import

Start from the YAML or CSV template in `supabase/seed/company_profiles/` (or download the YAML template from the app). JSON is also accepted by the local importer. The checked-in [`profiles/core_entities.json`](../profiles/core_entities.json) seed contains 52 cross-market company/instrument profiles, including bilingual aliases and five explicitly qualified industry-context relationships. The three leveraged ETF entries are conversation trackers only; they are not a ranking of Korean retail purchases or performance recommendations. The profile format supports ticker/exchange, Korean common name, KRX code, bilingual aliases, negative aliases, topics of interest, related-entity links with a relationship type and evidence note, and per-market/language terms.

Run `npm run import-profiles -- profiles/core_entities.json` for validation only. The compact JSON seed expands to KR/ko and US/en market profiles; topical event terms are stored separately from entity aliases so generic topics do not cause broad entity matches. Fix all warnings, especially missing Korean names, short/ambiguous aliases, and duplicate/contradictory aliases. Apply only after review with `npm run import-profiles -- profiles/core_entities.json --apply`; the command reads only `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` from the process environment or root `.env.local` and never prints their values. It upserts supplied company and market fields, preserves omitted market profiles, creates only listed relationships, and does not delete historical documents, profiles, or entity links.

Alias matching is literal and deterministic, not a probability. Negative aliases take precedence. The seed has 20 fruit-context negatives each for Apple and Amazon and 20 cocoa-context negatives for Kakao, covered by tests. This is a conservative initial seed, not a claim that aliases are exhaustive; inspect and extend false-positive tests as sources and watchlists expand. The legacy `MARKET-TALK` profile is a macro context stream, not an entity, and its documents are not connected to company-level entity metrics. The current production feed configuration supplies no cleared Korean discussion source, so importing profiles alone creates no evidence or metrics.
