# Source registry and access review

## The Conversation licensed expert analysis

The daily ingestion checks the direct Atom feeds for the Australia and U.S. editions. It accepts an item only when that item's feed entry carries an explicit Creative Commons attribution/no-derivatives rights statement, the author byline and publication date are present, and the original article link remains on the publisher's HTTPS host. Signal Scout retains only the headline unchanged, author names for attribution, date, original link, feed-edition label, and exact feed rights text; Atom summaries and article bodies are discarded. The source is classified as licensed expert analysis—not online conversation, breaking-news coverage, or independent cross-publisher corroboration. The two editions remain one publisher/operator; edition and language labels do not establish reader location or audience.

No account, API key, fee, or click-through rights acceptance is used. Each accepted record retains its own feed-provided rights statement; items missing the required notice are skipped. The feed responses are capped at 1.5 MB each, one request is made per edition per daily ingestion, and publisher-origin URLs are enforced.

References: [Australia edition Atom feed](https://theconversation.com/au/articles.atom), [U.S. edition Atom feed](https://theconversation.com/us/articles.atom), [The Conversation on its Creative Commons republication model](https://cdn.theconversation.com/static_files/files/1439/2018_Stakeholder_Report_The_Conversation.pdf).

## GDELT on-demand global news search

Explore can send one visitor-triggered query directly from the browser to the GDELT DOC API. It requests at most 25 results from the last seven days and keeps returned headlines, dates, language, country labels, and publisher URLs only in that visitor's browser; the app does not persist results or queries. The UI links to the publisher and credits GDELT. Its returned source-country field is a publisher/index label, not audience geography or origin of conversation. GDELT's terms permit free academic, commercial, and governmental use, and require citation plus a link to GDELT. The hosted API rate-limits requests to at most one every five seconds; this execution environment repeatedly received HTTP 429 even when requests were spaced, so scheduled server-side ingestion is not considered reliable. The direct-browser search surfaces provider rate limiting and does not retry. GDELT is a news index, not a discussion forum, and matching headlines do not prove independent publishers or constitute a lead.

References: [GDELT DOC API](https://blog.gdeltproject.org/gdelt-doc-2-0-api-debuts/), [GDELT terms of use and attribution](https://www.gdeltproject.org/about.html).

## Stack Exchange historical topic sample

The scheduled Stack Exchange connector makes the same 33 keyless, title-only queries across 11 communities, but now requests a 30-day publication window on each daily run. It retrieves only one page of up to 100 items per query (the API maximum); older or lower-ranked matches can be omitted, and overlapping query results are deduplicated. Only individually CC BY-SA 4.0 questions are persisted with author/profile, site, tags, and license attribution; bodies are discarded. This can seed the descriptive 30-day tag-share baseline sooner than waiting 14 daily ingestions, but does not turn the sample into a complete archive. Missing days remain missing, tags are not translated/merged, and the entire sample still comes from one Q&A operator. The run is capped at the existing 33 requests/day and continues to respect API backoff.

References: [Stack Exchange search API](https://api.stackexchange.com/docs/search-advanced), [API throttles](https://api.stackexchange.com/docs/throttle), [content licensing](https://stackoverflow.com/help/licensing).

## Mastodon public hashtag viewer

The optional /explore viewer requests a hashtag timeline directly from one of four fixed public Mastodon servers (mastodon.social, mastodon.online, mstdn.jp, mastodon.world), caps each API response at 20, filters to public non-boost statuses, shows author/origin and canonical links, honors content warnings, and does not persist posts or derive metrics. Visitors may request one server or compare one bounded sample from all four; overlapping status URLs are shown once with the server views that returned them, and per-view counts are not summed. A separate topic-discovery action makes one public `GET /api/v1/trends/tags?limit=10` call to each of the four servers, then keeps each server's internally ranked suggestions distinct; selecting a hashtag only fills the visitor's search box. Official API docs describe those as tags used more frequently in the past week, with internal trending scores periodically recalculated—not a stable or comparable cross-instance metric. Live probes returned HTTP 200 and ten tags from each server; the samples included multilingual tags. No trend/post data or queries are persisted. Each server is a separate federated view, not a country/language proxy; posts can overlap and include relays, RSS syndication, and automated accounts. This is not a complete fediverse or representative population sample. The Mastodon API permits servers to disable public timeline access. mastodon.social's current user terms took effect 2026-08-31 and state that authors retain ownership and license Mastodon GmbH to operate and maintain the service; they do not provide Signal Scout with a blanket license. Keep this a transient public client and re-review rights before introducing scheduled ingestion, retention, or aggregate analysis. Other instances set their own terms. An instance may restrict or rate-limit access; do not authenticate or route around those controls.

References: [Mastodon trending-tags API](https://docs.joinmastodon.org/methods/trends/#view-trending-tags), [Tag entity](https://docs.joinmastodon.org/entities/Tag/), [Mastodon hashtag timeline API](https://docs.joinmastodon.org/methods/timelines/#view-hashtag-timeline), [rate limits](https://docs.joinmastodon.org/api/rate-limits/), [mastodon.social current Terms of Service endpoint](https://mastodon.social/api/v1/instance/terms_of_service), [Terms of Service API structure](https://docs.joinmastodon.org/entities/TermsOfService/).

## GDELT outlet-country and language exploration

The optional /explore GDELT viewer makes one direct browser query for a seven-day capped news sample and accepts validated `sourcecountry:` and `sourcelang:` filters (outlet location and original publication language). It does not store search text or results. Country filters describe the publisher's location, not readers or audience; counts of returned publisher domains do not imply independent ownership. GDELT's DOC API supports multilingual search across monitored coverage, but index and language coverage are incomplete. GDELT has repeatedly returned HTTP 429 in this execution environment; the UI surfaces the upstream limit without retries or proxying around it. References: [GDELT DOC API documentation](https://blog.gdeltproject.org/gdelt-doc-2-0-api-debuts/), [GDELT terms](https://www.gdeltproject.org/about.html).

## Browser-only evidence brief

On /explore a visitor may deliberately add citation metadata from the currently displayed on-demand results and write their own topic, working thesis, alternatives, and disconfirmation question. The selected references and notes live only in volatile page memory until navigation/reload; there is no local/session storage or server/database write. The Markdown export/copy occurs only after a visitor clicks the corresponding button and stays on the visitor's device/clipboard. Exports include source links and attribution metadata, not Mastodon post text, Lemmy post bodies, or Wikimedia snippets. Stack Exchange license/author metadata, Mastodon author-link/no-blanket-license caution, GDELT publisher/GDELT attribution, Lemmy author attribution, and Wikimedia history/license reminder accompany their respective citations. This is a human-authored notebook, not generated thesis analysis, a lead score, source-independent sample, or investment recommendation. Re-review before adding autosave, accounts, sharing, quotes/excerpts, uploads, or any server persistence.

Lead review's licensed Stack Exchange topic observations link to Explore with the exact tag in a URL fragment. Explore reads and removes that fragment before rendering the prefilled topic inputs; the fragment is not sent in the HTTP request. Phrase-based search boxes and the brief are prefilled but never submitted automatically. Mastodon remains hashtag-only. Lemmy results may contribute only a title/link/author citation after the visitor confirms the instance's age requirement and terms; post bodies and query results are not retained.

## Wikimedia on-demand article-talk search

Explore searches namespace-1 talk pages on a visitor-selected English, Spanish, German, Korean, or Japanese Wikipedia. It requests at most 20 relevance-ranked text-search results; archived pages are excluded and only pages edited within 90 days are displayed. That timestamp is the page's edit time and snippets may quote older discussion. Results and query remain in the visitor's browser; no content is persisted, counted, or fed into leads. Contributor credit is linked through the talk page's history. Wikimedia contributions are generally licensed under CC BY-SA 4.0 and GFDL, subject to project and imported-content exceptions; review the page itself. Talk pages are editorial collaboration, not representative public conversation. API requests identify the app with the required `Api-User-Agent`; respect the current rate policy and `Retry-After`.

References: [MediaWiki search API](https://www.mediawiki.org/wiki/API:Search/en), [Wikimedia API access policy](https://www.mediawiki.org/wiki/Wikimedia_APIs/Access_policy), [Wikimedia API rate limits](https://www.mediawiki.org/wiki/Wikimedia_APIs/Rate_limits), [Wikimedia Foundation Terms of Use](https://foundation.wikimedia.org/wiki/Terms_of_Use?useformat=mobile).

Reviewed 2026-09-30. A source being public or technically reachable does not itself authorize collecting, retaining, or republishing its content. Keep excerpts short, retain attribution/source links, respect terms and access controls, and disable a connector when intended use is uncertain.

## Independent discussion candidates reviewed, not integrated (2026-10-01)

- **Codidact:** independent, community-run Q&A network with a documented public family of communities; its FAQ says most posts are CC BY-SA 4.0 but site/category/author-selected licenses can differ, so any connector would require item-level license filtering. Its current Terms say using the Service constitutes acceptance. No Codidact API request or integration was made because the active project instruction forbids accepting terms on the user's behalf. Revisit only after the user accepts the terms and the public API/access policy and selected community licenses are verified. References: [Codidact Terms of Service](https://codegolf.codidact.com/help/tos), [Codidact licensing FAQ](https://codegolf.codidact.com/policy/codidact-faq).
- **LessWrong:** the current linked MIRI terms expressly prohibit spiders, scrapers, or other automated website access; no requests or integration were made. Its content licensing also varies and is not a blanket reusable-content grant. References: [LessWrong FAQ linking to terms](https://www.lesswrong.com/posts/2rWKkWuPrgTMpLRbp/lesswrong-faq-1), [linked terms](https://intelligence.org/files/PrivacyandTerms-Lesswrong.com.pdf).
- **Effective Altruism Forum:** its forum addendum describes CC BY 4.0 user content, but access itself constitutes acceptance of its terms. The linked general terms limit use of the CEA sites to personal, non-commercial benefit. No API request or integration was made. References: [EA Forum Terms of Use Addendum](https://fm-prod.effectivealtruism.org/termsOfUse), [Effective Altruism general terms](https://www.effectivealtruism.org/terms-and-conditions).
