# Source registry and access review

Reviewed 2026-09-30. A source being public or technically reachable does not itself authorize collecting, retaining, or republishing its content. Keep excerpts short, retain attribution/source links, respect terms and access controls, and disable a connector when intended use is uncertain.

| Source | Current state | Access / terms note | Rate or operational constraint | Fallback |
|---|---|---|---|---|
| Publisher RSS/Atom | No direct publisher feeds currently configured | Production/local feeds were Google News redirect feeds. These fail the publisher-domain contract, are rejected by the connector, and their legacy rows are hidden in the public UI. Future direct feeds require a source-specific terms review; RSS availability is not a blanket republication license. | Connector retries only transient errors; long `Retry-After` pauses further retries. | Keep RSS off until permitted direct feeds are configured. |
| NAVER Search API / Search Trend | Not implemented; not cleared for Signal Scout | NAVER is migrating Search API and Search Trend to NAVER API HUB. Only applications completed before 2026-07-31 are scheduled to keep legacy Developer Center access through 2027-06-30; new applications moved to the Hub. The Hub currently advertises a basic free policy plus metered paid expansion (not a guaranteed forever-free service). More importantly, the current API terms prohibit copying/storing/caching results except narrow temporary service-continuity/history windows, providing data to third parties, and using it in AI. Signal Scout's persistent storage, cross-market analysis, and public display do not fit those stated limits. Do not enable absent written authorization and a compliant redesign. | Quota and pricing depend on API Hub product settings and may change. Never enable paid usage. | Use only independently authorized direct publisher feeds; do not scrape Naver results or treat its search output as a forum corpus. |
| SBS News RSS | Public RSS exists; disabled | SBS states its RSS service is authorized for personal, non-commercial use only; commercial use requires contacting SBS News in advance. A shared research product is not assumed to qualify as personal RSS use. | Publisher sets feed availability; no ingestion configured. | Do not use without written permission for collection, retention, and public display. |
| Kyunghyang / Hankyoreh RSS | Public RSS exists; disabled | Kyunghyang says RSS is for personal subscription and sharing content on websites/cafes or for profit requires prior copyright-holder permission. No permission for Signal Scout is on file. | Publisher sets feed availability; no ingestion configured. | Do not use without written permission. |
| Korean government RSS (e.g. MOFA) | Candidate for official-policy context only; not configured | Official RSS directories confirm feed availability, but an RSS subscription link alone does not settle automated retention, excerpt display, and downstream analysis rights. Government releases are institutional communications, not public investor conversation or forum sentiment. Review copyright/reuse terms per agency before collection. | No API key indicated by RSS directory; feed limits not established. | Keep separate from news/forum samples; never present as Korean investor discussion. |
| Korea MOIS press-release RSS | Production feature flag enabled; first successful scheduled run pending | MOIS lists a direct press-release RSS feed. Its copyright policy permits reuse only for MOIS-owned works carrying KOGL Type 1 and requires specific attribution. The connector checks each linked article page for the Type 1 mark and retains only the headline, source link, date, and license metadata—never the RSS full-text description or article body. This is government policy context, not investor conversation. | No key or fee. Rate limits are not stated. One feed request per scheduled ingestion; only recent title matches are checked, capped at five article-page license checks. | Keep separate from discussion/news class comparisons. |
| Maeil Business News (MK) RSS | Candidate; not configured | Publisher provides direct economics and securities RSS endpoints, but the public RSS page does not itself grant rights for redisplaying excerpts in a public information service. Leave off pending terms/permission review. | Feed-specific limits not documented on the RSS directory page. | Do not replace Google News with this feed until reviewed. |
| Electronic Times (ETNews) RSS | Disabled | Publisher lists RSS endpoints, while its content-rights page says use in information services requires prior agreement/formal contract. No feed configured. | Terms and commercial service fees require provider confirmation. | Exclude unless permission is obtained. |
| Hacker News Search API | Currently enabled in deployed release; local code now fails closed pending rights approval | Official API exposes public comments; Signal Scout links to the exact comment. YC's current Terms of Use restrict commercial use and separately restrict copying/distribution of site content absent authorization. Public API access does not by itself settle third-party excerpt/display rights. The deployed release remains unchanged; the local implementation requires a second explicit rights-approval flag before ingestion and withholds HN-linked records from evidence, metric, and lead views after deployment. This is a narrow U.S.-leaning sample, not a Korea/U.S. matched pair or representative investor sample. | Signal Scout uses Algolia's API and keeps alias queries bounded. | Do not substitute HN for Korean forums. Keep disabled and obtain counsel/source confirmation before reuse or scaling public display. |
| GDELT DOC | Disabled | Project says data is no-fee and redistribution requires citation/link attribution. Product connector previously received HTTP 429. | Do not retry early or route around throttling. | Keep disabled; no current news fallback is configured. |
| Bluesky public AppView | Disabled | Official API reference says public GET endpoints can be unauthenticated. Deployment previously received HTTP 403; access/terms not established for current use. | Do not bypass 403. | No forum substitution; report unavailable coverage. |
| SEC EDGAR | Disabled | Official API access requires a descriptive User-Agent; no contact identity is configured. | SEC states maximum of 10 requests/second. | Link to public SEC filings manually; do not invent a contact. |
| OpenDART | Not implemented | Official OpenDART API is generally free but requires registration and an issued 40-character key; no account/key has been requested. | Quotas are published and may change; terms allow service limits. | Manually inspect official disclosures; no scraping. |
| Kakao/Daum Cafe Search API | Technically available; disabled pending written permission | The official API searches public Daum Cafe posts and requires a Kakao REST API key. Current published free quota lists 30,000 Cafe Search requests/day (subject to change). However, Kakao's Developer Terms and Operating Policy prohibit copying, translating, publishing, broadcasting, or otherwise providing data obtained through the service without prior Kakao approval. A free quota is not a content-reuse license. Do not ingest or display Cafe results until written permission explicitly covers Signal Scout's collection, retention, analysis, and public display. | Keep paid API usage disabled; never configure a wallet/card. Enforce a hard local request budget below free quota if approved. | No Korean forum feed; report the limitation rather than scraping Naver/Toss/DC Inside. |
| Reddit Data API | Not implemented; explicit approval required | Reddit Help currently says API data access requires a request and explicit approval. API calls require OAuth and an identified User-Agent. Reddit's terms permit limited copy/display within an app for app users but prohibit other uses without permission; commercial use requires a separate agreement. Signal Scout should not access Reddit until its use case is approved and retention/deletion duties are implemented. | Free access is conditional and rate-limited; availability/terms can change. Do not create an app or submit an access request without user approval. | HN remains the only enabled discussion API and is U.S.-leaning, not representative. |
| Naver Finance, Toss, DC Inside and other Korean forums | Not implemented; legal review required | No automated collection until source-specific terms/access/retention/display review confirms permission. No login, anti-bot bypass, or scraping. | Unknown; do not assume keyless means permitted. | State clearly that no Korean forum feed is active. |
